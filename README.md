# 제주 관광 동향 분석 에이전트 (가칭)

제주 AI Agent 챌린지 출품작이다. 도민·소상공인·공무원이 일상어로 물으면 제주데이터허브 관광 데이터를 찾아 결합·분석하고, 차트와 해석을 근거·한계와 함께 돌려준다.

**현재 상태 (2026-11-03)**: 데이터 수집과 파일 정리까지 진행했다. 에이전트 코드(분석 도구, LLM 루프, 화면)는 아직 없다. 지금 있는 코드는 `scripts/` 의 데이터 스크립트 2개뿐이다.

이 파일은 전체 안내이고, 데이터별 상세와 주의사항은 [data/README.md](data/README.md) 에 있다.

## 에이전트 설계

**사용자와 질문 예시**

| 사용자 | 질문 |
| --- | --- |
| 관광업 소상공인 | "서귀포 관광지 방문객은 몇 월에 가장 많아?" |
| 관광 담당 공무원 | "2024년에 코로나 전(2019)보다 회복된 관광지는?" |
| 도민·연구자 | "비 오는 날 버스 승차가 얼마나 줄어?", "레저 목적 입도객은 요즘 늘었어?" |
| 처음 온 사람 | "관광 관련 데이터 뭐가 있어?" |

**기능**. MVP(F1~F5)만 먼저 완성한다. F6~F8은 여유가 있을 때만 한다.

| 기능 | 하는 일 | 쓸 데이터 (`data/processed/`) | 범위 |
| --- | --- | --- | --- |
| F1 데이터 길잡이 | 질문에 맞는 데이터 추천, 항목·기간 설명, 센터 전용 데이터 안내 | 허브 카탈로그 + 센터 명세 73종 (**폴더에 없음**, 아래 참고) | MVP |
| F2 추세·순위 | 기간별 추세, 전년 대비, 순위 | `spot_visitors_monthly`, `nationality`, `foreign_visitors_monthly`, `visit_purpose`, `domestic_floating_monthly` | MVP |
| F3 비교·회복률 | 두 기간·집단 비교, 코로나 전 대비 회복률 | `spot_visitors_monthly`, `nationality`, `visit_purpose` | MVP |
| F4 계절성 | 월별 성수기·비수기 패턴 | `spot_visitors_monthly` | MVP |
| F5 날씨 영향 | 강수·기온에 따른 버스 승차 변화(평소 대비) | `asos_daily` 또는 `weather_daily` + `bus_route_daily` | MVP |
| F6 사건 영향 | 코로나·사드 등 전후 비교(개입 분석) | `spot_visitors_monthly`, 입도객 | 확장 |
| F7 간단 예측 | 향후 3~6개월 관광객 전망(계절형 모델) | `spot_visitors_monthly` | 확장 |
| F8 최신 혼잡 예측 | 관광공사 집중률 API 조회 | 외부 API | 확장, 온라인 시만 |

**작동 흐름**

1. 질문 입력(또는 예시 질문 버튼)
2. 의도 파악: LLM이 질문을 "도구 + 조건"으로 변환 (예: 추세, 성산일출봉, 2019~2024)
3. 되묻기: 관광지명·기간이 모호하면 후보를 보여주고 선택받음
4. 실행: 미리 검증한 파이썬 분석 함수가 로컬 DB에서 계산
5. 검증: 결과 없음·기간 밖·표본 부족 점검, 해석문의 숫자가 계산 결과와 같은지 대조
6. 답변: 차트 + 3줄 해석 + 근거(데이터명·기간·계산 방법) + 한계 + CSV·그림 다운로드

**지켜야 할 원칙**

- 데이터 선택, 분석 방법 선택, 되묻기는 에이전트가 스스로 한다.
- LLM은 숫자를 만들지 않는다. 모든 수치는 분석 함수의 계산 결과다.
- 데이터를 외부로 보내지 않고, 상관관계를 인과로 단정하지 않는다.
- 센터 오프라인 PC에서 동작하는 것이 기본이고, 외부 API는 선택 옵션이다.
- 추천 챗봇이 아니라 분석 도구다. 예측은 핵심이 아니라 도구 중 하나다.

**기술 구성 (계획)**

| 부분 | 선택 | 비고 |
| --- | --- | --- |
| LLM | 기본: Ollama 로컬 7~8B급(4bit) / 옵션: 클라우드 API | GTX 1060(6GB)에 맞는 크기. 후보 2~3개를 한국어·도구 호출 정확도로 비교해 결정. 불안정하면 LLM 역할을 도구 선택·문장 작성으로 제한하고 키워드 규칙으로 대체 |
| 에이전트 | 파이썬 도구 호출 루프 직접 구현 | 프레임워크 최소화로 설치·재현을 단순하게 |
| 데이터 | 전처리 스크립트 → DuckDB/Parquet | 인코딩·날짜 오류·관광지명 표기 통일 |
| 분석·차트 | pandas, statsmodels(확장), Plotly | |
| 화면 | Streamlit (브라우저, 로컬 실행) | 채팅 + 예시 질문 + 데이터 목록 |
| 실행 | `run.bat` 한 번 클릭, 오프라인 설치 패키지 | 모델·라이브러리 미리 포함 |

**기획서에 쓸 차별점**

1. 제주 특화 허브 데이터 결합: 관광지 50곳 16년치 + 입도객 목적·국가별 + 유동인구 + 버스 + 기상
2. 정해진 화면이 아니라 자유 질문, 답마다 사용 데이터·계산 방법·한계 표시
3. 센터 오프라인 PC에서 로컬 모델로 동작
4. 센터 전용 데이터 73종(카드·POS, 유동인구, 국적별 와이파이 등)은 개발에 쓰지 않고 '센터 탑재 시 분석 범위 확장'으로 제안

**중단된 수집**

| 소스 | 받은 구간 | 진행 | 멈춘 응답 |
| --- | --- | --- | --- |
| `weather_daily` | 2018-01-01 ~ 2020-08-15 | 958/2,646일 | HTTP 403 `Today's quota is full` |
| `tour_local` | 2018-01 ~ 2021-07 | 43/106개월 | HTTP 429 |

둘 다 끝까지 받아야 CSV가 만들어지고, 남은 양으로 보아 각각 약 2일 걸릴 것으로 추정한다. 하루 약 1,000회라는 한도는 호출 수로 어림한 값이고 초기화 시각은 확인되지 않았다. 이어받기 전에 한도가 풀렸는지 먼저 확인한다.

**결정이 필요한 것**

- `bus_daily`: 한 달치만 받기로 했는데 어느 달인지 정하지 않았다. 지금 CSV는 2024-01-01~07 표본이며, 새 기간을 받으면 CSV가 그 기간으로 덮어써진다 (`raw/api/bus_daily/` 원본은 남는다).
- `weather_daily`를 끝까지 받을지: 2025-03-30까지만 제공되고 표기 이상 여부도 아직 확인하지 않았다. 안 되면 2026-11-02까지 받아 둔 `asos_daily`(기상청)로 대체한다.

**개발 전에 알아야 할 데이터 문제**

- F1에 필요한 허브 카탈로그와 센터 데이터 목록 v12(엑셀)가 이 폴더에 없다. 파일을 넣거나 새로 만들어야 한다.
- `spot_visitors_monthly` 에는 시군 구분이 없다. `spot_visitors_2024` 에 있는 36곳만 시군을 붙일 수 있어, "서귀포 관광지" 같은 질문은 50곳 전부에 답하지 못한다. 나머지 14곳은 따로 매핑해야 한다.
- 버스 CSV 2개가 합쳐 약 1.1GB(1,400만·1,580만 행)다. 원래 계획의 "수만 행" 가정과 다르므로, 일 단위로 집계한 표를 만들어 쓰고 제출 zip 용량도 따로 확인해야 한다.
- 버스 데이터는 2022-08-12부터 약 100일이 비어 있고, 인원 정의가 파일마다 다르다. F5는 `bus_route_daily` 에서 `actType == "승차"` 만 쓴다.
- 이용자 유형별 버스 데이터에 관광객 항목은 없다.
- 유동인구는 2022-07에 집계 방식이 달라진 것으로 보여 이 시점을 넘는 비교를 하지 않는다.
- 방문목적별 입도객의 실제 시작은 2018-01이 아니라 2021-08이고, 국가별 입도객도 2021-08부터다. 이 둘로는 코로나 전(2019) 대비 회복률을 계산할 수 없으므로 F3의 회복률은 2019년 값이 있는 관광지 월별 데이터로 계산한다.
- 주요 관광지점 입장객 2025년분이 11-14에 허브에 등록될 예정이다. 등록되면 반영 여부를 판단한다.

## 폴더 구조

```
jeju-agent/
├─ README.md                   이 파일
├─ .env                        API 키 (공유·제출 금지)
├─ scripts/
│  ├─ fetch_api.py             API 수집. 받은 구간은 건너뛰고 이어받음
│  └─ prepare_files.py         직접 받은 파일 정리
├─ data/
│  ├─ README.md                데이터별 상세, 주의사항
│  ├─ raw/api/                 API 원본 JSON (약 0.04GB)
│  ├─ raw/files/               직접 받은 파일 사본 (약 1.05GB)
│  └─ processed/               정리본 CSV 17개 (약 1.13GB)
└─ 내가 직접 받은 데이터/        내려받은 원본 (약 1.05GB)
```

`prepare_files.py` 는 `내가 직접 받은 데이터/` 를 읽어 `data/raw/files/` 로 복사한다. 내용이 같은 사본이지만 이 폴더가 없으면 스크립트가 실패하므로 지우지 않는다.

## 환경 설정과 실행

Python 3.14.3, pandas 2.3.3, requests 2.33.1, openpyxl 3.1.5로 실행했다. `requirements.txt` 는 아직 없다.

```
pip install pandas requests openpyxl python-dotenv
```

프로젝트 루트의 `.env` 에 키를 넣는다. 다른 PC로 옮길 때는 새로 만들거나 따로 복사한다. 데이터를 다시 받지 않고 `processed/` 만 쓴다면 필요 없다.

```
HUB_API_KEY=        # 제주데이터허브
DATA_GO_KR_KEY=     # 공공데이터포털
VISITJEJU_API_KEY=  # 비짓제주
```

저장 경로를 바꾸려면 `DATA_RAW_DIR`, `DATA_PROCESSED_DIR` 를 추가로 지정한다 (기본값 `data/raw`, `data/processed`).

```
python scripts/fetch_api.py --list              # API 소스 목록
python scripts/prepare_files.py --list          # 파일 소스 목록
python scripts/prepare_files.py all             # 직접 받은 파일 정리

# 중단된 수집 이어받기
python scripts/fetch_api.py weather_daily --start 20180101 --end 20250330
python scripts/fetch_api.py tour_metro tour_local --start 20180101 --end 20261004
```

`prepare_files.py` 의 `foreign_visitors_monthly` 는 `nationality.csv` 가 있으면 값을 대조해 불일치 건수를 출력한다. 없으면 대조만 건너뛴다.
