# 제주 관광 동향 분석 에이전트 (가칭)

제주 AI Agent 챌린지 출품작이다. 도민·소상공인·공무원이 일상어로 물으면 제주데이터허브 관광 데이터를 찾아 결합·분석하고, 차트와 해석을 근거·한계와 함께 돌려준다.

**현재 상태 (2026-11-06)**: 데이터 수집과 파일 정리, 로컬 DB 적재, 보유 데이터 카탈로그, 시험 문제 19개까지 끝냈고 분석 도구 9개와 LLM 호출 루프를 구현했다. 도구 값은 시험 문제의 기대값과 대조했고, Gemini 무료 모델로 시험 문제를 풀어 봤다 ([결과](#실제-모델-시험-결과)). **한 모델로 16문제를 끝까지 푼 적은 아직 없다.** Streamlit 화면(`app.py`)과 `run.bat` 을 만들었고, 소비 분석을 위해 허브 카드 파일 2종을 DB에 넣었다 (받은 5종 중 나머지 3종은 값만 확인). 로컬 모델은 시작 전이다.

이 파일은 전체 안내이고, 데이터별 상세와 주의사항은 [data/README.md](data/README.md) 에 있다. 작업 기록, 데이터 목록, 할 일은 [노션](https://app.notion.com/p/40c1b69caff781798fe4c360fe6269b2)에서 관리한다. 프로젝트 문서는 이 두 곳만 갱신한다.

**작동 흐름**

1. 질문 입력(또는 예시 질문 버튼)
2. 의도 파악: LLM이 질문을 "도구 + 조건"으로 변환 (예: 추세, 성산일출봉, 2019~2024)
3. 되묻기: 관광지명·기간이 모호하면 후보를 보여주고 선택받음
4. 실행: 미리 검증한 파이썬 분석 함수가 로컬 DB에서 계산
5. 검증: 결과 없음·기간 밖·표본 부족 점검, 해석문의 숫자가 계산 결과와 같은지 대조
6. 답변: 차트 + 3줄 해석 + 근거(데이터명·기간·계산 방법) + 한계 + CSV·그림 다운로드

**지켜야 할 원칙**

- 데이터 선택, 분석 방법 선택, 되묻기는 에이전트가 스스로 한다.
- LLM은 숫자를 만들지 않는다. 모든 수치는 분석 함수의 계산 결과다.
- 데이터를 외부로 보내지 않고, 상관관계를 인과로 단정하지 않는다. 단 클라우드 모델을 쓰는 동안에는 질문과 도구의 집계 결과가 그 서비스로 전송된다. 개발에 쓰는 Gemini 무료 사용분은 입력과 응답이 Google 제품 개선에 쓰일 수 있어 개발 시험에만 쓴다. 허브 목록은 제3자 제공이 금지되어 어떤 모델을 쓰든 LLM에 건수만 알리고 항목은 화면에 직접 보여 준다.
- 설치 때는 인터넷을 쓸 수 있지만, 설치 뒤에는 인터넷 없이 동작하는 것이 기본이고 외부 API는 선택 옵션이다.
- 추천 챗봇이 아니라 분석 도구다. 예측은 핵심이 아니라 도구 중 하나다.

**기술 구성 (계획)**

| 에이전트 | 파이썬 도구 호출 루프 직접 구현 | 프레임워크 최소화로 설치·재현을 단순하게 |

| 화면 | Streamlit (브라우저, 로컬 실행) | 채팅 + 예시 질문 + 데이터 목록 |
| 실행 | `run.bat` 한 번 클릭, 비전공자용 설치 매뉴얼 | 센터 담당자가 매뉴얼대로 설치한다. 모델과 패키지는 인터넷으로 받을 수 있다 ([제출 용량](#제출-용량)). Streamlit은 기본 설정이면 다른 PC에서도 접속할 수 있어 `.streamlit/config.toml` 에서 `localhost` 로 제한하고 사용 통계를 끈다. 지금 `run.bat` 은 실행만 하고 설치는 하지 않는다 |

**분석 도구 설계**

LLM은 SQL을 쓰지 않고 아래 9개 도구(`agent/tools.py`)와 조건만 고른다. 표와 계산은 도구가 정하므로 이중 집계 같은 실수를 코드에서 막는다.

| 도구 | 기능 | 주요 인자 | 코드에서 막는 실수 |
| --- | --- | --- | --- |
| `find_data` | F1 | 질문 키워드 | 센터 전용·제외 데이터를 쓸 수 있는 것처럼 안내, 허브 목록 파일이 없을 때 목록을 아는 것처럼 답함 (넣는 방법을 안내한다) |
| `describe_data` | F1 | 데이터 ID | 항목·기간을 문서에서 옮기다 낡은 값을 말함 (DB에서 읽는다) |
| `resolve_spot` | 공통 | 관광지 이름 | 없는 관광지, 모호한 이름을 임의로 하나로 정함. 후보가 여럿이면 되묻는다 |
| `get_trend` | F2 | 지표, 필터, 기간, 월·연 단위 | 일부 달만 있는 해를 온전한 해와 비교 |
| `rank_values` | F2 | 지표, 기간, 필터, 상위 N | 달 수가 다른 대상을 같은 순위에 올림 |
| `compare_periods` | F3 | 지표, 기간 A·B, 묶음 기준 | 두 기간 모두 12개월 값이 없는 대상의 회복률 계산, 자료가 없는 기간과 비교 |
| `get_seasonality` | F4 | 지표, 필터, 기간 | 자료가 있는 관광지 수가 달라 생기는 왜곡, 코로나 기간 포함 |
| `get_day_pattern` | F2 | 일별 지표, 필터, 기간 | 요일마다 날 수가 다른데 합계로 비교, 평일 공휴일을 평일에 포함, 날이 적은 자료로 단정 |
| `analyze_weather_effect` | F5 | 날씨 변수, 구간, 기간 | 이상일 포함, 계절·평일/휴일을 맞추지 않은 비교 (`bus_weather_daily` 만 쓴다) |

`get_trend`, `rank_values`, `compare_periods`, `get_seasonality`, `get_day_pattern` 은 표 이름 대신 **지표 ID** 를 받는다. 지표 목록이 표, 값 컬럼, 허용 필터, 제공 기간, 고정 주의사항을 정한다.

| 지표 ID | 표 | 지키는 조건 |
| --- | --- | --- |
| `spot_visitors` | `spot_visitors_view` | 내·외국인 합산 여부를 결과에 표시 |
| `arrivals` | `arrivals_monthly` | 입도객 합계는 이 표만 쓴다 |
| `visit_purpose` | `visit_purpose` | `classType` 없이는 합산하지 않는다 |
| `foreign_arrivals` | `foreign_arrivals_monthly` | 국가 필터 |
| `air_passengers` | `airport_passengers_monthly` | 입도객이 아니라 항공 이용자 지표로 표시, 방향 필터 필수 |

#### 답할 수 있는 범위

[reference/coverage_questions.json](reference/coverage_questions.json) 에 실제 사용자가 물을 만한 질문 30개를 두고 `scripts/check_coverage.py` 로 모델 없이 도구를 돌려 본다 (2026-11-06 초안). 가능 19개, 일부 4개, 불가 7개다. 빈틈은 렌터카·이동 3개, 2021년 이전 입도객 2개, 1인당 소비·소비·매출·숙박·축제·크루즈·세부 지역 각 1개다. 소비·매출을 메우려고 허브 파일 5종(업종별 성별 카드 이용 정보, 메뉴별 외식업 매출액, 성별 카드 이용금액 비율, 시간대별 카드 이용금액 현황, 요일별 카드 이용 건수 비교)을 받아 값을 확인했고, 업종별과 시간대별 2종을 DB에 넣었다 (2026-11-06). 질문은 개발자가 쓴 초안이라 이 비율이 실제 수요를 나타내지는 않고, 도구가 값을 돌려준다는 뜻이지 모델이 맞게 답한다는 뜻은 아니다.

실제 사용자에게 묻지 못해 질문마다 답으로 무엇을 결정하는지(`decision`)와 넣은 근거(`basis`)를 적었다. 상권 분석 서비스 항목 7개, 제주 방문관광객 실태조사 항목 3개, 대회 목표 3개, 제주연구원 소상공인 조사 2개이고 **15개는 근거를 찾지 못한 추정이다.** 공무원 질문은 모두 추정이다. 근거 연결은 개발자의 판단이고, 수요를 직접 조사한 자료는 찾지 못했다.

수요의 간접 지표로 허브 목록의 등록 후 연평균 조회 수를 봤다 (2026-11-06). 상위 100건의 주제 비중을 전체 비중과 견주면 소비·매출 8% / 1.5%, 관광객·입도 7% / 1.6%, 인구·유동 4% / 1.2%, 숙박 3% / 0.9%, 음식·상권 4% / 1.7%, 렌터카 2% / 1.7%, 택시·교통 3% / 4.9%, 관광지·콘텐츠 6% / 22.9% 다. 제목 낱말로 나눈 주제이고 건수가 작으며, 조회 수에는 대회 참가자나 자동 접속이 섞였을 수 있어 수요의 증거로는 약하다.

#### 실제 모델 시험 결과

2026-11-05, Gemini 무료 모델. 무료 한도(아래) 때문에 문제마다 모델과 프롬프트 판이 다르므로 **정확도 수치가 아니라 문제를 찾기 위한 시험이다.** `run_eval.py` 는 기대 도구, 꼭 말할 내용, 미확인 숫자를 자동으로 본다. 각 문제의 마지막 실행 기준으로 자동 통과는 11개다.

2026-11-06에 카드 자료를 넣은 뒤 새 문제 4개를 `gemini-3.5-flash-lite` 로 풀었다. Q02, Q18, Q19 통과, Q17 은 1위 한식 음식점업만 답해(`top_n` 1) 2위 항목이 빠졌다. 숫자 대조는 모두 통과했다. 다만 Q17 에 "음식 관련 소비가 큰 비중", Q18 에 "낮 시간대인 오후와 저녁" 같은 도구 결과에 없는 해석이 들어갔고, 근거에 지표 ID(`card_industry`)가 그대로 나왔다. 위 표의 Q02 는 카드 자료를 넣기 전 문제의 결과다.

찾은 문제와 조치는 다음과 같다.

- `gemini-2.5-flash` 는 2025~2026년을 미래로 보고 도구 없이 "자료 없음"이라 답했고 "2010~2023년 자료" 같은 없는 기간을 지어냈다. 오늘 날짜와 도구 필수 지시를 프롬프트에 넣고, 도구 없는 답을 되돌리고, 연도 대조를 더하자 Q10, Q15가 통과했다. 로컬 모델에서도 같은 일이 생길 수 있어 전환 때 먼저 볼 항목이다.
- 작은 모델은 도구가 준 값을 빠뜨리기 쉬워, 빠지면 안 되는 값은 `limits` 문구에 숫자로 넣었다.

**Gemini 무료 한도 (2026-11-05 응답에서 확인)**: `gemini-3.6-flash` 는 하루 20회다. 이 모델을 다 쓰자 `gemini-3.5-flash` 도 같은 메시지로 막혀 한도를 함께 쓰는 것으로 보인다. `gemini-2.5-flash`, `gemini-3-flash-preview`, `gemini-3.5-flash-lite` 는 그 뒤에도 응답했다. 한 문제에 약 1~4회 호출하므로 16문제를 한 모델로 하루에 끝내기 어렵다. 입력은 호출당 약 4천 토큰부터이고 문제당 약 8천~2만 5천 토큰이었다. 503 혼잡 응답도 잦다 (`gemini-flash-latest`, `gemini-3.7-flash`, `gemini-3.8-flash` 는 시험 때 503).

**기획서에 쓸 차별점**

1. 제주 특화 허브 데이터 결합: 관광지 50곳 16년치 + 입도객 목적·국가별 + 유동인구 + 버스, 여기에 기상청 ASOS 기상 자료를 더함

4. 센터 전용 데이터 73종(카드·POS, 유동인구, 국적별 와이파이 등)은 개발에 쓰지 않고 '센터 탑재 시 분석 범위 확장'으로 제안

### `bus_daily` 추가 수집

개발과 별개로 2026-09부터 과거로, **자동 실행 없이 사용자가 요청한 날에만** 받는다. 하루 약 15일치(한도 추정치 기준)이고 서버 오류가 나면 줄어든다. 받지 못해도 기능이 막히지는 않는다. 11-12부터 검증과 기능 동결이므로 그 뒤에 받으려면 DB가 바뀌어도 되는지 먼저 확인한다.

"오늘 데이터 받아줘" 같은 요청을 받으면 이 순서로 한다.

1. `python scripts/backfill_bus.py --status` 로 받은 날, 다음에 받을 날, 지난번 기록을 확인한다. 지난번에 행 수 확인 실패로 멈췄으면 그 원인부터 본다.
2. `python scripts/backfill_bus.py` 를 백그라운드로 실행한다. 기록은 터미널이 아니라 `data/backfill_bus.log` 에 남으므로, 종료 코드가 아니라 `--status` 로 결과를 확인한다.
3. 받은 날 수와 멈춘 이유(한도, 서버 오류, 행 수 확인 실패)를 알린다. 한도나 원인이 확인되지 않은 부분은 추정이라고 밝힌다.
4. `DB 반영 완료` 기록이 있으면 `python scripts/check_eval_questions.py` 를 돌리고, [data/README.md](data/README.md) 의 `bus_daily` 기간·행 수·누락 추정일, 이 문서의 진행 상황, 노션의 데이터 목록과 작업 기록을 고친다.

스크립트가 지키는 것은 다음과 같다.

- 한도에 걸리면 바로 끝낸다. 서버 오류면 10분마다 다시 시도하고 그날 23:30에 끝낸다. 받던 날은 저장되지 않아 다음에 처음부터 다시 받는다.
- 하루치는 API 총 건수와 행 수가 같을 때만 저장한다.
- 한 달이 다 차야 DB에 넣는다. 새 DB를 따로 만들어 원본·시험 문제 대조를 통과하면 바꾸고, 실패하거나 DB가 열려 있으면 CSV와 DB를 그대로 둔다. 이전 DB는 `data/jeju.prev.duckdb` 에 남으며 제출에 넣지 않는다.
- 2026-10 값은 달이 늘어도 바뀌지 않는다. 누락 판정을 그 달 기준으로 하고, 시험 문제는 2026-10으로 조건을 고정했다.

**기상 자료는 `asos_daily` 만 쓴다.** 허브 `weather_daily` 는 2025-03-30까지만 제공되고 958/2,646일에서 수집을 멈췄으므로 쓰지 않는다. 받아 둔 원본은 `data/raw/api/weather_daily/` 에 남아 있고 CSV는 만들지 않았다. ASOS는 외부 데이터이므로 출처와 의존성을 데이터 활용 명세에 적는다.

**개발 전에 알아야 할 데이터 문제**

- **허브 목록은 대회 페이지 데이터 탭의 파일만 쓴다** (`제주데이터허브 데이터목록_20261105.xlsx`, 2026-11-05 게시판 답변). 프로그램으로 직접 수집하는 방식은 어렵다는 답변을 받아 예전에 직접 받은 목록은 삭제했다. **이 파일과 그 내용을 담은 DB는 제3자 배포가 금지되어 제출 zip과 GitHub에 넣지 않는다.** 그래서 DB에 넣지 않고 `scripts/hub_list.py` 가 `data/raw/` 의 엑셀을 직접 읽으며, 실행하는 곳에서 파일을 직접 받아 넣게 한다. 파일이 없으면 허브 목록 검색만 안 된다. 새 파일에는 설명 항목이 없어 이름·분야로만 찾는다.
- 센터 명세 v12는 공개 자료라 원본 엑셀을 zip과 GitHub에 넣어도 되고 F1에 써도 된다 (같은 답변).
- 센터 명세 v12에 따르면 73종 중 24종(데이터 22종, 코드표 2개)은 반출 가능이다. 교통 10종, 와이파이 6종, 환경 6종이고, 시간대별 정류소 승하차(`3-04`)도 있다. 받지는 않았다.
- 시군 구분은 `dim_spot` 에 50곳 모두 넣었다. 허브 값 36곳, 비짓제주 10곳, 웹 검색 1곳이다. 목석원·제주미니미니랜드·제주조각공원 3곳은 근거가 약해 신뢰도를 낮음으로 표시했다. 3곳 모두 자료가 2014-06 이전에 끝난다.
- 버스 CSV 2개(약 1.1GB)는 집계해서 DB에 넣었다. DB는 약 35MB다.
- 버스 데이터는 2022-08-12부터 약 100일이 비어 있고, 인원 정의가 파일마다 다르다. F5는 `bus_weather_daily` 만 쓴다.
- **버스 2,385일 중 187일은 원본 일부 누락·중복으로 보여 F5에서 뺀다** (`isAbnormalDay`). 근거와 기준은 [data/README.md](data/README.md) 에 있다. 이 비율은 강수 구간과 관계없이 약 5~8%라 호우일이 더 많이 빠지지는 않는다.
- 연간 비교와 회복률은 비교하는 두 해 모두 12개월 값이 있는 관광지만 계산한다. 2019·2024년 기준 27곳이다. 2024년 값이 0인 4곳, 2개월뿐인 아쿠아플라넷을 그대로 계산하면 회복률이 틀린다.
- **`bus_daily` 2026-10의 5일(10-01, 10-12, 10-23~25)은 합계에서 뺀다.** 31일 중 이 5일만 행 전부 정류소 이름이 비어 있고, 이용 인원도 평일·휴일별 중앙값의 0.02~0.36배다. 4일이 호우와 겹치지만 비가 없던 10-01도 같은 양상이고 감소폭이 과거 호우일보다 훨씬 커서, 비로 줄었다고 보지 않고 원본 일부 누락으로 추정한다. 제공처에 확인한 것은 아니다. 근거는 [data/README.md](data/README.md) 에 있다.
- `bus_daily` 의 `stationId` 는 `bus_stops` 와 형식이 달라 연결되지 않는다. 빈 이름은 같은 ID의 다른 날 이름으로 채우고(5일의 이용 인원 기준 99.99%), 위치는 이름으로 연결한다.
- `bus_daily` 는 다른 버스 자료와 인원 정의가 달라 더하거나 비교하지 않는다. 2024-01 초 평일 승차 합계가 `bus_boarding_daily` 의 약 6배다.
- `tour_local` 은 제주시와 서귀포시를 더해 제주 전체로 쓰지 않는다. 합계가 `tour_metro` 보다 외지인 기준 약 1.7배 크다. 제주 전체는 `tour_metro` 를 쓴다.
- 이용자 유형별 버스 데이터에 관광객 항목은 없다.
- 유동인구는 2022-07에 집계 방식이 달라진 것으로 보여 이 시점을 넘는 비교를 하지 않는다.
- **`visit_purpose` 는 전체를 더하면 2배가 된다.** 여행형태 3종과 방문목적 6종이 같은 사람을 나눈 값이다 (48개월 모두 두 합계가 같다). 입도객 합계는 `arrivals_monthly` 를 쓴다.
- 방문목적별 입도객의 실제 시작은 2018-01이 아니라 2021-08이고, 국가별 입도객도 2021-08부터다. 이 둘로는 코로나 전(2019) 대비 회복률을 계산할 수 없으므로 F3의 회복률은 2019년 값이 있는 관광지 월별 데이터와 항공 이용자 지표로 계산한다.
- 2019년 대비 규모는 제주 공항 도착 이용자(`airport_passengers_monthly`)로 본다. 도민 등을 포함하고 배편을 포함하지 않으므로 입도객 수로 부르지 않고 "항공 이용자 지표"로 표시한다. 2024년은 2019년의 94.5%다. 2021-08~2025-07에는 입도객 합계의 1.07~1.09배(연평균)로 안정적이었으나 2021년 이전에도 같은지는 확인할 수 없다.
- 배편으로 항공 지표를 보정할 수 없다. `ferry_passengers_yearly` 는 2021~2023년 연간 값뿐이고, 승객의 68~75%가 도내 항로(마라도·가파도)이며, 제주-뭍 항로는 완도·우수영만 있고 방향 구분이 없다. 2019년 배편 자료는 찾지 못했다.
- **허브 자료의 이용 조건을 대부분 확인하지 못했다.** 규칙은 데이터를 적법하게 쓸 수 있어야 한다고만 하고, 데이터별로 zip에 넣어도 되는지는 정하지 않았다. 지금 계획은 사용 데이터 정리본과 DB를 zip에 넣는 것이고 카탈로그의 사용 데이터 22건 중 20건의 이용 조건이 `미확인` 이므로, 제출 전에 대회 게시판으로 확인한다.
- **카드 자료의 `내국인` 은 도민을 뺀 방문객처럼 움직이지만 제공처 정의는 아니고, 제주 전체 소비액도 아니다.** 관광 목적만 나눌 수 없어 `관광객(추정)` 으로 표시한다. 요일·성별 비율·외식 파일은 도민과 관광객을 나눌 수 없어 넣지 않았다. 상세는 [data/README.md](data/README.md) 의 카드·외식 파일 확인 결과 절에 있다.
- 주요 관광지점 입장객 2025년분이 11-14에 허브에 등록될 예정이다. 등록되면 반영 여부를 판단한다.

| 허브 목록 xlsx | 0.1MB | | 측정 | **넣으면 안 됨** |

- 모델과 Ollama를 빼면 `processed/` 를 넣어도 약 0.3GB다.
- 매뉴얼에 모델명, 버전, 다운로드 경로, 설치·실행 방법을 구체적으로 적고, 비전공자도 그대로 따라 할 수 있게 쓴다. 대회 데이터 탭에서 허브 목록 파일을 받아 `data/raw/` 에 넣는 단계도 적는다.
- 모델 크기는 이제 제출 용량이 아니라 GTX 1060(6GB)에서 돌아가는지로 정한다.
- 제출 전에 실제 zip을 만들어 다시 재고, **허브 목록 파일이 들어가지 않았는지 확인한다.**
- 기획서 20MB는 아직 재지 않았다. 차트 이미지 해상도만 주의하면 될 것으로 보며, 초안이 나오면 잰다.

## 환경 설정과 실행

Python 3.14.3 기준이다. `requirements.txt` 에 52개 패키지의 버전을 고정했다. 2026-11-04에 깨끗한 가상환경에서 오프라인 방식(`--no-index`)으로 설치해 충돌이 없는 것, DB 열기, 스크립트 목록 출력, Streamlit 기동을 확인했다. 2026-11-05에 `anthropic` 을 더해 새 가상환경(`.venv`)에 온라인으로 설치해 `check_agent.py` 를 돌렸고, 오프라인 설치는 다시 하지 않았다. 전체 데이터 재생성은 이 환경에서 시험하지 않았다.

```
pip install -r requirements.txt
```

프로젝트 루트의 `.env` 에 키를 넣는다. 다른 PC로 옮길 때는 새로 만들거나 따로 복사한다. 데이터를 다시 받지 않고 `processed/` 만 쓴다면 필요 없다.

```
HUB_API_KEY=        # 제주데이터허브
DATA_GO_KR_KEY=     # 공공데이터포털
VISITJEJU_API_KEY=  # 비짓제주
GEMINI_API_KEY=     # Gemini로 에이전트를 돌릴 때 필요
```

`LLM_PROVIDER` 는 `gemini`(기본), `ollama`, `claude` 중 하나다. `LLM_MODEL` 로 Gemini·Ollama 모델을 고르고(Gemini 기본 `gemini-3.6-flash`, Ollama는 필수), `LLM_BASE_URL` 로 주소를 바꿀 수 있다.

Claude를 쓰려면 `ANTHROPIC_API_KEY` 를 넣는다. Claude 구독과 별개로 API 요금이 든다. `CLAUDE_MODEL`(기본 `claude-opus-5-5`), `CLAUDE_EFFORT`(기본 `medium`)로 모델과 노력 수준을 바꿀 수 있고, 거절된 요청을 서버가 다른 모델로 다시 실행하도록 `fallbacks: "default"` 를 켜 두었다. Haiku는 이 설정을 지원하지 않아 그대로는 쓸 수 없다.

저장 경로를 바꾸려면 `DATA_RAW_DIR`, `DATA_PROCESSED_DIR`, `DATA_DB_PATH` 를 추가로 지정한다 (기본값 `data/raw`, `data/processed`, `data/jeju.duckdb`).

```
python scripts/fetch_api.py --list              # API 소스 목록
python scripts/prepare_files.py --list          # 파일 소스 목록
python scripts/prepare_files.py all             # 직접 받은 파일 정리
python scripts/build_db.py                      # 로컬 DB 생성, 원본과 대조
python scripts/hub_list.py                      # 허브 목록 파일 확인 (대회 데이터 탭의 파일을 data/raw/ 에 넣은 뒤)
python scripts/check_eval_questions.py          # 시험 문제 기대값을 DB와 대조
python scripts/check_agent.py                   # LLM 없이 도구, 루프, 화면 확인
python scripts/check_coverage.py                # 질문 30개를 답할 수 있는지 모델 없이 확인
python -m streamlit run app.py                  # 화면 실행 (run.bat 과 같다). 질문하면 무료 한도를 쓴다
python scripts/ask.py "2024년 입도객은?"         # 질문 하나
python scripts/run_eval.py --ids Q03,Q05        # 시험 문제 채점. 답변은 data/eval_runs/ 에 저장. 무료 한도를 쓴다

# 기간을 지정해야 하는 수집 (받은 구간은 건너뛴다)
python scripts/fetch_api.py tour_metro tour_local --start 20180101 --end 20261004
python scripts/fetch_api.py bus_daily --start 20261001 --end 20261031
```

`prepare_files.py` 의 `foreign_visitors_monthly` 는 `nationality.csv` 가 있으면 값을 대조해 불일치 건수를 출력한다. 없으면 대조만 건너뛴다.
